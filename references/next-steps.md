# Review 后的改进与研究方向

只在 Review 后需要整理可选建议时读取。复用本次审查、最低标准、用户反馈和验证证据，不另开第二轮全仓库评估或重读整个会话。修复及其定向复核使用 [review-followup.md](review-followup.md)，不把旧问题未闭环掩盖为未来方向。

## 选择方向

- **已确认问题**沿用 Review 的证据和优先级。会破坏最低标准的问题要明确指出，不能藏入未来愿望清单。范围内最小修复按统一流程与现行授权执行；只读等限制仍优先。
- **可选改进**只从已观察到的维护成本、重复劳动、用户体验或测试缺口提出；说明证据、预期收益和可验证的小步。不是新验收要求。
- **研究假设**只提出有具体疑问的探索：要回答什么、为什么值得看、最小实验或要查的一份权威资料、何种结果支持继续或停止。证据不足标为假设，不虚构性能数字、费用或确定结论。

可选改进与研究方向合计最多3项，其中研究最多1项；不用凑数，无候选可省略该部分。普通 Review 的建议限本阶段相关补全，全量 Review 可提出有依据的内部模块整理手段，说明影响、迁移步骤与回归保护。默认只依据已覆盖材料；成本如需写则用低／中／高的粗略估计，不假装精确计算 token。

建议按影响、证据强度和验证成本排序，从确定问题及上述候选中选一个“优先下一步”，给出最小动作和验收／实验判定条件。关键未知未解决时优先核验，不用新功能掩盖缺口。

## 简短交付

按实际内容组织，不要求空表格或固定字数：

1. Review 范围、结论、实际验证及未覆盖项；最低标准是否仍成立。
2. 确定问题：位置、触发条件、影响、证据；没有则明确本范围未发现可确认问题。
3. 后续候选：类型、依据、收益、估计成本、最小动作与判定条件。
4. 有剩余问题时给优先下一步，以及哪些可选动作尚未获准；已修复并复核完成时如实收束。

建议写入本阶段已有记录的一小节或直接在回复交付，不为每次 Review 建立新的路线图、规则文件或任务。旧建议与本次内容相同则沿用，不重复扩展清单。用户没有选下一步时结束，不为获取选择反复提示；明确选择后才开始对应工作。

## 研究与扩展 Skill

本次 Review 不默认联网。只有用户要求查资料／搜索扩展 Skill，或明确批准具体研究时，才按该范围检索。先复用已有权威链接；缺资料时默认一组不超过2个定向查询，读取最多3个直接相关的一手来源，能回答问题即停止。用户明确要求更广调查时按其范围调整。

如方向涉及工具或 Skill，先按需读取 [扩展 Skill 选型](extensions.md)。只推荐解决已知缺口的一项，核对宿主支持、触发频率、读取范围、额外模型成本及写入行为；仅搜索或推荐不安装。安装、调度其他 Agent、修改规则／配置和外部写入遵守用户实际授权，不从 Review 同意推导。

已有完整交接授权时，交接只携带建议及其“未批准”状态，继续原目标；建议不能自动替代已确认的接续第一步。
