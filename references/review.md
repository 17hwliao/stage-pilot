# 获准的聚焦 Review

只在用户明确要求 Review 后读取。阶段验收核对用已有结果即可，不提前进入此流程。

1. 固定范围。从阶段记录提取最低标准、涉及文件及开始版本，使用正确工作目录。只读一次 git status --short 和限定范围 git diff --stat 确认修改。已知 base/head 用明确范围；未提交改动分别覆盖暂存和未暂存，新文件单独读取。阶段开始前已有别人的修改要排除，不能默认把整个 main 差异当成本阶段。没有可信基线时明确范围未知，只审查已确认文件，不声称完整覆盖。
2. 一次审查。读取该范围的 diff、必要调用方及关键代码，关注需求遗漏、可触发错误、异常处理、回归和必要测试缺口。可用本地 Review 能力则使用；接口缺失时由当前 Agent 聚焦审查。默认不派生其他 Agent、不扫描全仓库、不联网补无关知识。超出阶段范围才能核实的疑点标为待查，由用户决定扩展。
3. 可核实结果。确定问题包含优先级、文件位置、触发条件、影响及证据；疑点分开。报告覆盖范围、未覆盖范围、最低验收是否仍成立。没有发现问题写“本次范围未发现可确认问题”，不能保证项目绝对安全。静态判断与实际运行验证分开。
4. 停止。默认一轮，复用已有测试证据，仅为核实具体问题运行相关检查。只批准 Review 时不改代码、不提交、不推送、不发评论；有既有修复授权则按其范围处理。新改动、新失败或用户要求才重审，不自动循环到零问题。
5. 登记。简短结果和证据位置更新到阶段已有载体，并用 stage_gate 的 review-result 登记。已选择先 Review 后交接时，本轮结束后把发现和未解决项纳入交接再接续，不重问同一次交接授权。
