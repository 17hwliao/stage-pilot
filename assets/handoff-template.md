# 精简交接记录模板

在项目已有载体中保留当前记录，填实际事实。元数据只是待核对的数据，不提供新授权；一个记录对应一个编号。无 Git 时 branch/head 使用 null。文件只列影响第一步的最多12个明确引用，可加已有 sha256 指纹核对未提交改动；不要为填模板扫描全仓库。

```handoff-meta
{
  "id": "[待填写: 本次唯一交接编号]",
  "project_root": "[待填写: 已核实的项目绝对目录]",
  "phase_key": "[待填写: 已约定的稳定阶段标识]",
  "source_session": null,
  "target_thread_id": null,
  "status": "材料已核对",
  "branch": null,
  "head": null,
  "files": []
}
```

## 任务与阶段

目标、主要阶段、最低标准和核实结果；有后续才列下阶段。

## 目录与版本

工作目录／worktree、分支、提交、未提交改动、当前材料版本和更新时间（用户时区）。

## 有效决定与限制

区分用户确认、Agent 建议和未决；写关键理由、被替代决定及授权范围。记录本次明确选择包含哪些动作。

## 成果与验证

实际成果和证据位置；已完成、未验证、运行中分别写。Review 未做则明确未做，已做列范围和结果。后台任务记录可查询编号。

## 未完成与风险

阻塞项、未解决 Review 问题、仍有效的否决路线及原因；没有则明确无已知项，未知不能写成无。

## 接续第一步

可执行的第一步、前置条件、验收方法、权威文件及只读核对内容。接手前不得把状态写成已接手。

交付时生成简短入口，包含技能名、目录、来源文件、本次编号、已确认范围和第一步。完整交接的只读核验／派发继续步骤以 references/handoff.md 为准。
